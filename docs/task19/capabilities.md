# ragy capability and verification matrix

This matrix describes the implementation after TASK13–18, checked against the public code on 2026-10-06. TASK19 final reports identify the exact accepted source and executed profiles. A local test, HTTP fixture or bridge fake is not verification against a running external service. Scope predicates, policy authority, original source retention and callback cooperation remain host contracts; capability flags do not implement IAM.

| Path | Implemented contract | Verification class and limits |
|---|---|---|
| Root retrieval, typed filters, fusion and decorators | Mandatory binding propagation, truthful native/rank-only scores, one RRF contribution per identity per ranking, cache/projection capability preservation and owned coverage | Local unit/race and external BYOT composition. Host filter/codec/identity behavior must be stable; unsupported guarantees fail closed. |
| Managed lexical | Exact BM25 over admitted inventory, mandatory scope and pinned publication; repeated fresh ledger gates and bounded LRU snapshot entries | Actual local lifecycle/BM25 integration and APFS profiles. Payload is volatile; metadata alone cannot reconstruct it. Entry capacity is not an arbitrary metadata-byte quota. |
| Managed graph | Pinned lifecycle or explicitly immutable host basis; node/edge scope and conflict admission before adjacency/traversal; original shared supports | Actual local traversal/lifecycle tests. Required selected-fact admission capacity is separate from output limits; metadata and support admission still cost work. Volatile facts require host restore/reindex. |
| Persistent dense | Exact declared-metric scan, matching embedding.Space, pinned publication, admitted records and revision-bound supports | Actual local Unix filesystem/race/reopen/adversarial tests; no ANN/distributed transaction claim. Scan and byte capacities are explicit. |
| Persistent tensor and tensor query | Exact late-interaction MaxSim within an explicit candidate universe; space/purpose checks and scope/publication preflight | Actual local candidate/profile tests. Candidate-only exactness does not guarantee exhaustive recall. Tensor metrics differ from dense metrics. |
| Source, hydration, ingestion and context artifact | Original UTF-8 mappings, declared source revisions, admitted hydration, bounded full formatted artifact, exact packed-input contributors and partial/derived coverage | Local parser/chunking/artifact tests and actual Python PDF engine when configured. No inferred factual correctness from provenance alone; subprocess memory containment and source retention remain host-owned. |
| Text and graph recipes | Explicit shared call/token/cost/deadline ledger; model-free routes remain model-free; planners/assessors and summaries consume admitted inputs | Local scripted-port/transport integrations and explicit evaluation profiles. Scripted models are not LLM quality evidence; reported unknown usage stays unknown. No agent loop or final-answer judge. |
| Lifecycle v2 / local filestore | Generation CAS, exact artifact reservations, crash-aware atomic local persistence, explicit eligible metadata retirement, durable registered metadata pins and reserved released IDs | Actual local APFS/flock/fsync/SIGKILL/restart/conflict tests. Finite snapshot capacity includes growing identities/fences/receipts; capacity fails explicitly. Pins do not preserve target/source payload. Custom Store must enforce ValidateReplacement. |
| Evidence v2 / core observation | Strict bounded, default-deny decision export with source re-admission; optional fixed-enum payload-free diagnostics | Go plus independent JSON Schema/relational fixtures and actual consumer recording. Evidence does not authenticate host identities; observer errors never repeat dispatch. |
| OTel adapter | Capability forwarding and safe attributes/outcomes/usage, optional core observer export | Local SDK/transport integration; explicitly selected convention subset. Core does not depend on OTel; collector availability/export durability are separate. |
| OpenAI, Gemini, Jina dense/multimodal/tensor; Cohere rerank | Explicit supported spaces/purpose, bounded single HTTP dispatch, official provider-specific wire shape, response validation and known/unknown usage | Official wire fixtures and negative HTTP tests; opt-in live checks separately reported. Unsupported provider modes reject before HTTP. Credentials, external model revisions and live service behavior are not inferred from fixtures. |
| pgvector, Qdrant, Elasticsearch | Host bridge with mandatory schema-bound scope filters and declared vector space where applicable | Local bridge/filter/score contract tests. Current live publication only: pinned publication is unsupported. Running PostgreSQL/Qdrant/Elasticsearch and driver guarantees require host integration verification. |
| Neo4j | Typed host Runner, projection and schema-validated traversal/upsert | Local Runner contracts. Scoped and pinned requests explicitly unsupported; no built-in database driver or implicit tenant isolation. |

Measured local scale and regressions are in [TASK18 profiles](../task18/results/scaling.md); finite storage/migration rules are in [lifecycle maintenance](../task18/lifecycle-maintenance.md). They describe the captured workload, not a universal production SLO.

Task12 reports and datasets remain dated historical evidence. Their requirement completion percentages do not measure production or agent readiness. TASK19 quality results must name corpus/split/config/model/tokenizer/usage identities and separate retrieval quality from resource compliance, source/citation correctness and live-service verification. Deterministic local quality gains cannot establish a universal default or external-agent resistance to retrieved instructions.
