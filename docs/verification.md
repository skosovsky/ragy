# Repeatable verification

The versioned `scripts/check-registry.json` is the contract for local checks, CI and release. It references separate development/release module inventories and exact toolchain pins, declares lane commands/dependencies/prerequisites, immutable consumer peer refs, parser versions, Linux image and PostgreSQL image. No runtime library depends on another library's tooling or a mutable remote Makefile.

| Command | Scope |
|---|---|
| `make test-fast` | Explicitly shortened cached module race cycle; not prerelease acceptance. `python3 scripts/verify.py test-fast --fresh --module adapters/openai` scopes developer checks. |
| `make test` | All required fresh module/script/example/consumer/actual parser/PostgreSQL lanes, plus mandatory Linux execution. |
| `make lint` | Exact Go/linter pins, baseline drift, config verification, formatter diff and all-module lint. |
| `make check` / `make acceptance` | Full prerelease registry: lint, tests, examples, generation inventory, integrations, consumers and Linux. |
| `make check-plan` | Machine-readable complete full plan, including optional profiles and prerequisites. |
| `make check-linux` | Disposable Docker full Linux profile, matching CI's canonical runner. |
| `make examples` / `make test-examples` | Compile examples without a second test loop. |
| `make fuzz FUZZ_SECONDS=2` | Bounded independent per-function fuzz campaigns; separate performance profile. |

Full profiles require committed tracked inputs, preserve unrelated untracked files and write artifacts outside the checkout. `--output /absolute/path` selects retained evidence; otherwise the runner prints its temporary artifact directory. JSON summary records every independent lane's PASS/FAIL/BLOCKED/SKIP, timing, commands, exact pins/peer refs/module inventory and Go test-level skips. Independent failures accumulate; failed prerequisites block their dependents. Required missing infrastructure or skips prevent success. Paid live providers and performance/manual evaluation are explicitly optional profiles; their absence never counts as executed evidence.

The Go compiler is selected with the exact `GOTOOLCHAIN` pin; the runner installs the pinned linter into a disposable cache if an explicit `GOLANGCI_LINT` executable is not supplied. Explicit executable overrides must still match the pins. `GOWORK=off`, `GOENV=off` and cleared `GOFLAGS` prevent ambient workspace/settings from changing coverage. Writable `GOCACHE`, `GOMODCACHE` and `GOLANGCI_LINT_CACHE` paths may be supplied for restricted hosts. `.golangci.yml` and its reviewed versioned `scripts/lint-baseline.yml` must match. The baseline includes separately commented repository exclusions for host-owned partial literals, contract fixtures and documentation probes; changes to these exceptions require updating the reviewed template as well. `exhaustruct_v5` remains enabled with the equivalent named ignore patterns on golangci-lint 2.14.0.

For native macOS/Linux checks provision an isolated Docker pgvector container with the registry image, label `ragy.task20=T09`, database `ragy` and `CREATE EXTENSION vector`; export its name as `RAGY_PG_TEST_CONTAINER`. Provision a Python venv with the registry's exact `pdfplumber`/`pypdf` versions and set `RAGY_PDF_PYTHON` to its interpreter. Full parser tests execute all actual parser chains; tagged PostgreSQL tests exercise the real database. Missing prerequisites are BLOCKED. `make check-linux` provisions equivalent dependencies and removes its isolated database after execution. Docker socket access is required for tagged tests; use a disposable development/CI Docker daemon. The container profile materializes the selected committed source in an independent clone, including when the caller uses a linked worktree.

CI provisions OS/services, then runs exactly `python3 scripts/verify.py check --source "$GITHUB_SHA"`. Only root `v*` tags trigger the full tag workflow; prefixed module tags do not create duplicate full runs. Tag runs additionally download and smoke-test the exact public version with checksum verification. Release checks the selected committed source and immutable rewritten candidate through this same full runner; candidate-only resolution uses a disposable exact-byte module proxy, never a future public tag or local module replace. Public verification uses the Go public proxy/sumdb and no replacements. See the [release runbook](release/runbook.md) for publication and safe recovery.
