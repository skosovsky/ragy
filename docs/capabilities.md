# ragy capability and verification matrix

This current guide describes the contracts after remediation T01–T19 (reviewed source `1672c0e`, 2026-10-07). The sequential remediation acceptance records identify exact source digests and executed profiles. A local test, HTTP fixture or bridge fake is not verification against a running external service. Scope predicates, policy authority, original source retention and callback cooperation remain host contracts; capability flags do not implement IAM.

## Reading verification evidence

Wire fixtures exercise serialization and negative response paths, not remote revision, credentials or token enforcement. Local unit/race/compiled composition verifies the stated host fixture. Actual PostgreSQL parity and actual configured Python PDF-engine profiles verify that captured runtime/server/corpus. Process-crash profiles verify restart/SIGKILL behavior on the declared filesystem; they do not certify hardware power loss or distributed filesystems. Semantic quality requires its named corpus/split/model/tokenizer/config and cannot be inferred from any of those profiles. Paid provider live checks are opt-in and a skipped check is not PASS.

The public `contracttest.RunScopedReadSuite` accepts host-owned intent/request/metadata and instrumented I/O fixtures; it checks direct leaf admission without relying on protective pipeline wrappers. Older struct-metadata and index suites use fixed fixtures. Passing either certifies only the supplied adapter/profile; it is not universal authorization, concurrency or deployment certification.

An external Codex CLI advisory runner is a legitimate semantic-review/evaluation port. Advisory conclusions must remain distinct from executable conformance and named quality measurements. This remediation does not require a new paid live reference-budget run. Historical checklist completion percentages remain requirement completion, not production readiness.
