Before implementation: every failure preserves caller HEAD/branch/index/files/refs; source/version persist before preparation, exact candidate and owned refs persist before publication. Retry never calculates another version. Successful remote inspection establishes none/partial/complete/collision by exact objects; failed observation is unknown and requires explicit inspection before retry. Atomic publication has no automatic fallback or blind deletion. Outstanding records must be inspected/resumed or explicitly finished before selecting another candidate.

Changes:

- `release_state.py` stores the candidate in Git common-directory `ragy-releases/active`, apart from caller payload. Atomic JSON replacement and file/directory synchronization persist schema/version/kind/source/candidate/modules/files/destination/expected refs/owned isolated refs/status/observation time. A process lock serializes commands across worktrees; active state validates scope/ref identities and rejects path symlinks/invalid records.
- `release.py` preserves isolated preparation and tags on every exit. Record is written before fetch/edit/tag; preparation can resume incomplete editing or individually created tags. A recovered commit must be the source itself or directly derive from its single parent, with allowlisted diff. Canonical manifest bytes are independently reconstructed from reviewed source plus permitted Go edits; incomplete working manifests must be original/canonical and recovered/stored commit manifests must match canonical bytes. Unreviewed module paths/external requirements fail closed. Stored candidate HEAD/clean state and differing owned/caller ref objects fail closed. Caller refs are never changed. Optional Git locks/refresh writes are disabled so read-only status checks also preserve caller index bytes when tracked file stat metadata changes.
- New/repeated release operations preserve the active version and candidate. `resume` continues it; `inspect` observes its exact remote objects; `finish` requires inspected complete state and archives record/repository before any new choice. Origin identity changes cannot silently redirect a stored release.
- Publication persists unknown before dispatch, performs only missing exact refs atomically, and reconciles remote regardless of transport exit. Complete is idempotent. Unknown blocks any push until inspect; collision blocks until explicit host resolution/inspect. Annotated tag objects differing from expected lightweight IDs are collisions even with matching peeled commits.
- [Public runbook](../release/runbook.md) documents these commands, states, failure/retry and archival rules. Persistent repositories replace T03 temporary cleanup; clean-consumer/module tooling remains T21/T22. No hardware power-loss or production publication claim is made.
