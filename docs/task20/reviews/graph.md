# Ragy graph review — b63d5e19

Scope: graph contracts/managed read path, graphingest extraction/resolution/history/materialization, graphexpand and graphsummary. Source unchanged. Reviewed current package READMEs and tests. Two confirmed defects; design decisions below are not additional proven runtime defects.

## G-F01 — P2: Extraction ignores earlier shared attempt deadline

Refs: `graphingest/extraction/extraction.go:54–64`, `:160–181`; `graphingest/extraction/README.md:30–32`; `recipe/budget/budget.go:87–98`.

`Extract` creates only its own `Duration` context. Unlike graphexpand/graphsummary, it never calls `ledger.Context`. The ledger checks its deadline at Reserve, but Settle deliberately permits late accounting; nothing subsequently enforces the earlier attempt deadline. Thus a model dispatched before the attempt expires can use the full local duration and its payload is accepted after the attempt expires. README explicitly promises that earlier parent/attempt deadline suppresses all payloads.

Confirmed public-API overlay repro `/tmp/ragy-graph-extraction-review_test.go`, using existing fixture: ledger deadline +5s, extraction duration60s. The model sees a context deadline 55 seconds later than the ledger deadline. It advances the shared injected clock by6s and returns valid two-entity output. Extract returns `(entities=2, err=nil)` with clock past ledger deadline. Host clock and model are cooperative, no arbitrary hostile callback required. Diagnostic test intentionally PASSES when reproducing existing defect.

Fix: compose adapter context with shared attempt context; make deadline gates enforce the actual earliest deadline under the declared injected-clock contract, without treating settle success as deadline permission. Preserve accounting on expiry. No retries, no scheduler. An injected-clock leap after Reserve must not escape the deadline gate; simply installing a wall-clock timer addresses cooperative elapsed time but not that deterministic case.

AAA acceptance: (1) model receives min(parent, attempt, local) deadline; (2) valid model completion beyond earlier attempt returns DeadlineExceeded and zero payload with usage settled; (3) clock advance during model/projector/clone yields same suppression; (4) earlier parent/local deadlines preserved; (5) just-before-deadline success. Use controllable clocks/barriers, no sleep-based flaky timing.

## G-F02 — P2: Distinct identity keys silently merge through UTF-8 repair in hash encoding

Refs: `graphingest/resolution/resolver.go:147–150`, `:197–218`, `:236–249`, `:288`, `:397–400`.

Canonical IDs hash `json.Marshal([]string{namespace,key})`. Go JSON repairs malformed UTF-8 to U+FFFD. Resolver validates decision keys/names/namespaces only for emptiness; relation key likewise. Distinct nonempty Go strings therefore produce the same canonical ID, without the host identity policy declaring equivalence. With equal display names the groups are silently merged and supports unioned; different names cause a protocol failure instead of preserving distinct identities. This is an encoding collision, not a SHA256 collision.

Confirmed public resolver overlay `/tmp/ragy-graph-resolution-review_test.go`: keys `string([]byte{0xff})` and `string([]byte{0xfe})`, namespace prod, same display label. Output: one entity, nil error, two traces with different keys but identical `entity:d61001fbed62eda4b8dea7abb76e13853101cb65848185715bc36dc136de9704` canonical ID. Source supports are ordinary valid locators. Input callback returns distinct explicitly supplied identities; no custom marshaler involved. Extraction validation does not protect host-generated canonical keys. The relation-key path has the same source-level defect; entity path executed.

Fix choose explicit identity contract: reject invalid UTF-8 before grouping/hashing (recommended for JSON-facing identities), or use a byte-exact framed encoding if arbitrary byte keys are intentional. Cover config ontology/policy identifiers and history compatibility coherently; do not silently rewrite keys. Document migration implications if canonical hash framing changes. Valid UTF-8 behavior should remain stable if strict validation alone suffices.

AAA: malformed namespace/key/name and relation key fail with zero result before grouping; U+FFFD itself stays valid; framing distinguishes tuple boundaries; equal valid decisions still merge; distinct valid decisions do not. If byte keys intentionally supported, property-test injectivity of framing rather than JSON canonicalization.

## Separate design/oddity decisions

1. **Keep graph ingestion inside ragy.** Source-bound fact extraction, provenance, retrieval traversal and summary evidence are retrieval-domain responsibilities. They do not require a new universal agent library. Host owns ontology, aliases, policies, model transports and lifecycle driving. Keep current independent typed ports; do not add harness modes, UI, scheduling or answer-agent state.
2. **Resolution README is stale.** Its last paragraph says package does not yet supply a source extractor, summary recipes or complete materialization/history integration, while neighboring packages and pipeline now do. Rewrite as package boundaries and link the actual composition, not an obsolete roadmap disclaimer.
3. **Source-local relation closure is deliberate but restrictive.** materialization requires both endpoint nodes supported by the same requested source, not merely globally existent (`ErrMissingEndpointSupport`). Retain fail-closed rule, give a cross-document relation example and explain host pre-materialization policy. Do not invent endpoint supports as a convenience fallback.
4. **Same identity with different display name errors.** `entities` checks only `Identity.Name` consistency after canonical hash match. Explicitly document that Name is canonical identity metadata, not per-mention label. Consider `CanonicalName`; host handles synonyms. No automatic first/latest winner.
5. **Comparable generic kind permits semantically odd types.** TKind/TRel allow arbitrary comparable values including structs/pointers/floats; equality of kinds and history JSON fidelity then depend on host. Document stable comparable enum/value requirements rather than add reflection constraints or a universal ontology.
6. **`Unresolved.Kind` is an untyped string while other states are named.** Introduce a small named entity/relation mention-kind type or document constants; `Kind` currently overloads fact category and host ontology kind. A clean break could use `MentionKind` with constants.
7. **Snapshot history is a declared record, not recomputation proof.** Capture validates support associations/cardinality but does not rerun ontology, reconstruct groups, or prove policy truth. This is correctly disclosed; maintain that boundary and make examples retain actual resolver result. Do not advertise Capture as validation of arbitrary Result.
8. **History `maxSupports` also caps fact/variant populations.** boundedRecord/boundedResult reuse one limit for multiple dimensions. Separate maxFacts/maxSupports only if host needs independent sizing; otherwise document exact accounting, especially duplicate support occurrences before union. Avoid exposing apparent independent limits that share semantics silently.
9. **History JSON byte limit is post-serialization.** maxBytes bounds accepted payload, not peak Marshal allocation or custom callback work. README already requires bounded pure faithful JSON callbacks; add explicit peak-memory limitation and pre-bounded BYOT payload expectation. No custom streaming serializer framework unless real workload justifies it.
10. **History file store portability and durability.** FileStore only compiles on darwin/linux; record/snapshot code is portable. Package README should explicitly state platform availability. Host-prepared durable root is required even though Append calls MkdirAll; existing doc honest, keep crash/unknown-append recovery instructions. No automatic record retention/deletion/background cleanup.
11. **Quadratic support unions / variant grouping.** resolver mergeVariant and history union use repeated linear equality/Contains; graphsummary union/subset similarly. Finite caps prevent unbounded admitted counts, not linear complexity. Benchmark accepted upper-bound inputs first. Use map[source.Locator] for dedup with stable encounter order where useful; arbitrary attribute equivalence remains host-driven. Do not add a generic indexing engine preemptively.
12. **Extraction MaxInputBytes only counts source text.** Its ModelInput also includes ontology/configuration strings and JSON framing. Unlike graphsummary, extraction never checks serialized full envelope bytes. Current field comment/README semantics need to say source-text bound clearly, or add a separately named full envelope bound. CountInputTokens must account for full actual provider request. This is design hardening, not another proven existing promise violation.
13. **Repeated original-source authorization in graphsummary is intentional but potentially expensive.** Refresh all communities before and after each map and again before reservation plus final Resolve creates approximately calls×supports admission work. Retain fail-closed freshness; document complexity and decide whether host's cheap captured lease can batch checks. Never cache positive authorization without a freshness contract.
14. **Selected citations are not information-flow taint.** Model sees all snippets yet output retained supports are only Selected indices. Later Resolve reauthorizes selected supports. Current docs explicitly promise structural association, not semantic truth. State whether revoking an unselected model input must revoke derived text; if desired, separate complete derivation dependencies from user-facing selected citations. Do not pretend LLM Selected proves which input influenced output; this is a product policy decision, not a confirmed current-contract security bypass.
15. **Summary object authorization scope differs from returned results.** Summary hides text and forces Resolve, while a returned MappedText is owned admitted data that callers can retain. Explain one-time delivery vs future fresh reads. Do not add a faux revocable string wrapper or promise to claw back already-delivered bytes.
16. **Community coverage is set coverage only.** CoversMembership truth derives from declared snippet member lists, not prose quality. Keep the name/comment caveat and explicit external quality checks. MissingCoverage stops on first incomplete community; document why later maps are not attempted. Do not invent implicit retry/repair or scoring thresholds.
17. **Graph traversal result limit is rejection, not truncation.** Exceeding MaxNodes/MaxEdges fails zero payload; MaxAdmissionRecords counts duplicated selected versions before dedup/scope. This is clearly documented but needs a public usage example showing smaller depth vs raising capacity. Keep deterministic exhaustive failure instead of arbitrary map-order truncation.
18. **Managed graph volatile storage is a reference profile.** It cannot rebuild facts from manifests after restart; host basis, fact corpus persistence and distributed graph database are separate. Existing README correctly calls this out. Preserve explicit unavailable state; do not auto-fallback to current/raw graph when pinned managed inventory is absent.
19. **graphexpand default outcome policy is hard-coded.** A valid seed-only graph with no edges is Insufficient even if node content answers retrieval goal. This is a recipe heuristic, not a correctness defect under current contract. Document it or host-supply sufficiency outside raw traversal; do not embed universal semantic grading in managed.Adapter.
20. **Error precedence consistency.** graphsummary/extraction/graphexpand settle usage then gate expiry before joining provider/settle errors. They suppress payload correctly except G-F01, but hide simultaneous underlying usage/protocol failures from errors.Is. Coordinate with core recipe error-precedence task: join relevant causes while preserving non-skippable classification, not fallback on timeout. Parent retrieval reviewer owns core defect; this item is extension/acceptance scope, not a duplicate runtime defect.
21. **Materializer validates normalized graph but returns original typed metadata.** validateResult discards NormalizeSnapshot normalized result. Managed.Stage normalizes its own captured records; no proven safety breach. Explain ownership/normalization stage boundary to avoid callers assuming Build returns canonicalized BYOT metadata. Prefer one explicit normalization boundary rather than conversion chains.
22. **Config ergonomics need examples, not builder frameworks.** Five generic parameters + many mandatory callbacks are justified by independent domain/metadata/access boundaries but cumbersome. Provide smallest complete composition and lifecycle handoff example, describe pure/bounded/concurrent callback contract once with links. Avoid new DI container, universal registry, implicit model choices or defaults for policy.

## Positive assessment / not findings

No hidden model retries in graph extraction/summary. Structural support admission precedes identity/projector callbacks. Attribute and output clone boundaries are explicit. Resolver preserves contradictory variants, materializer rejects arbitrary winner selection, managed traversal removes conflicting/forbidden bridges before expansion. History filenames bind support inventory as well as payload digest, Append is atomic no-overwrite with explicit unknown-result recovery, and reads reauthorize before payload I/O. These mechanisms are purposeful and should not be deleted merely to shrink code. They remain cooperative host-port contracts, not a sandbox for arbitrary Go callbacks.
