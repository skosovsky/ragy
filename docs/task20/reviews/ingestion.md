## Confirmed defect

### ING-F01 — P2: layout accepts conflicting page payloads under one retained reference

- `layout/layout.go:100–114` validates physical page order, source lineage, representation difference and per-page shape, but does not require unique exact page references.
- `layout/project.go:71–85` projects each page into TextLocation with `[0,len(Text))`. TextLocation deliberately contains no page geometry; identity is the source.Reference plus byte range.
- `source/reference.go:13` defines Reference as one exact artifact/revision/representation; one reference cannot honestly mean two different retained text payloads.
- Public repro `/tmp/ragy-ingestion-repro.go` creates valid full-coverage two-page document, physical indexes 0 and 1, equal exact Reference, texts AAA and BBB. `Document.Validate` and `layout.Project` both return nil. Two outputs have identical ID/locator and different exact quoted text.
- Observed output: `layout validation=<nil> projection=<nil> count=2 identicalIDs=true text="AAA"/"BBB"`.
- Consequence: dedup/index upsert can discard or overwrite one page; subsequent exact locator resolution cannot retrieve both claimed originals. Not a claim of auth bypass or an observed PDF-adapter defect; external Parser outputs are public contracts.
- Fix: document-level uniqueness/admission for page retained references, before projection/callbacks. Audit analogous duplicate retained payload identity across cell/image/page kinds; do not blindly reject intentionally shared image media with distinct regions without defining permitted cases. Do not “fix” by adding physical page into a text locator hash while leaving an ambiguous source loader reference.
- AAA: arrange two valid ordered pages sharing reference with distinct equal-length text; act Validate and Project; assert error and no projected payload/ImageText call. Control with distinct references must produce independently resolvable text. Add duplicate reference with differing text length so avoiding only equal-span IDs is insufficient.

## Separate design decisions / oddities (not additional confirmed bugs)

1. **Overlap has fallback-only semantics.** `chunking/ranges.go:56–95,104–147` uses overlap only in fixedRanges after all separators fail. Probe NewRecursive(8,3,nil), “one two three four five six” returns ranges [0,7),[8,13),[14,18),[19,27), no overlap anywhere. README says sizes and overlap count runes but does not specify this limitation. Explicitly choose best-effort overlap and document it, or implement overlap between separator groups while keeping exact source ranges. Add readable examples/properties for both. Do not assert universally exact overlap without trimming policy.
2. **Markdown is a hash-line heuristic.** `chunking/ranges.go:150–170` treats trimmed `#anything` as heading, including fenced code, ignores Setext headings. Decide supported Markdown grammar and rename/document heuristic or implement proper block-aware boundary recognition. No reason to import an entire document rendering framework.
3. **Custom separators can discard non-whitespace delimiters.** `separatorRanges` skips delimiter bytes between output fragments. Explicitly state keep/drop policy, add punctuation and repeated delimiter tests. Original coordinate accuracy alone does not establish information coverage.
4. **Semantic segment coverage not enforced.** `sentenceTexts` checks ordered nonoverlap but permits dropped prefix/tail/non-whitespace gaps. Semantic groups recover gaps only inside a group; gaps across groups disappear. Contract says segmenter chooses boundaries; decide whether omission is allowed and require coverage (apart from whitespace) if not. Add custom segmenter contracts; avoid hallucinating semantic text.
5. **Default sentence segmentation is punctuation only.** Abbreviations, decimals and adjacent punctuation become artificial sentences; clarify baseline heuristic, keep BYO segmenter. No provider/model fallback.
6. **Contextual sorting after ordered map.** `chunking/chunking.go:529–531` sorts by Index though MapOrdered preserves input order; custom duplicate/out-of-order indices are not validated. Decide one Splitter ordering contract, validate it and remove redundant sort, or document sorting. Sorting should not silently rescue invalid chunk identity.
7. **Contextual output validation gap is a contract choice.** Base Splitter and ContextGenerator results pass through without ValidateChunk/UTF-8 Context checks. State whether trusted callbacks must guarantee these; lightweight validation before further generator calls is preferable to later failures. Do not classify arbitrary malicious callback behavior as a core security defect.
8. **Chunk validation granularity.** `chunking/chunk.go` permits Total0, does not validate InputSpan against content/source, and allows invalid UTF-8 unmapped Content/Context. It cannot validate absolute source bytes without source; expose distinctions between standalone chunk shape and splitter-result validation, instead of adding fake coordinates or assuming Total is always known.
9. **Projection partial-result asymmetry.** `chunking/project.go:171–193` returns completed docs on identity/metadata/document error, but nil on IndexText error. No documented partial contract. Prefer uniform all-or-nothing pure projection, or explicit partial API/typed progress. This does not itself publish chunks.
10. **Default identity fallback precedence.** `project.go:77–98` combines source descriptor with chunk SourceID/ID override and URI-derived MergeKey. Conflicting descriptor/chunk source identities are not rejected. Define identity authority and stable indexing across revisions/rechunking; make host overrides explicit. Current fallback is deterministic convenience, not a reason to add a global ID service.
11. **StorageID reused for all chunks.** Descriptor.StorageID overrides every projected chunk's default. Document this as source-level storage identity vs document ID; ensure projector example doesn't accidentally use it as unique chunk primary key. Rename if ambiguity persists.
12. **Metadata borrowing is intentional but needs end-to-end ownership docs.** built chunks reuse doc.Meta, contextual generators read concurrently, README requires immutability. Preserve BYOT; do not reflexively deep-copy with JSON. State borrowed result metadata too, and offer explicit host cloner only where independent snapshots are promised.
13. **Source reader architecture is justified.** `source/read.go` separates authoritative thin Catalog from admitted Loader, validates full batch before payload callbacks, clones then revalidates, checks freshness at boundaries, and has no latest fallback. Keep; no generic workflow framework needed. `documents.Hydrator` and layout.Resolver are narrow specializations rather than duplicate library orchestration.
14. **RawStore boundary is correctly explicit.** `documents/documents.go` calls out no scope/publication/retained guarantees. Ensure top-level examples route scoped hydration through Reader/Hydrator instead of FindByIDs; do not retrofit hidden auth into RawStore.
15. **Ingestion authorization vs Project binding.** layout.Input is already authorized. `layout.Project` freshness-gates supplied Binding, but does not prove document content belongs to that scope. Document this precondition directly on Project, not only package/Input. Model callbacks receive a binding, not automatic permission for arbitrary content. Host Catalog/Loader owns admission.
16. **Mapping wire strictness differs from locator/evidence.** `source/mapping_json.go:46–68` uses ordinary encoding/json+unknown-field rejection; duplicates, case-insensitive aliases, missing zero fields and malformed Unicode replacement are not rejected like strict locator/evidence wire. Choose and document strict persisted mapping contract; if strict, use existing shared wire validation approach with bounds. Current comments claim structural validation, not source authenticity, so this is contract hardening rather than an invented auth exploit.
17. **Reference/locator trust distinction must remain explicit.** SourceMapping unmarshal can structurally admit a falsely attested exact quote; docs correctly say exact source resolution certifies source text. Keep this caveat prominent and require authenticated resolution before externally trusting citations; no “cryptographic” digest can replace host authority.
18. **Potential quadratic range validation cost.** `layout/resolve.go:regionText` builds one mapping per word; `source.OriginalText` calls ByteSpan.ValidateText, which scans whole retained UTF-8 string. Large page with W selected words and N bytes has repeated O(W*N) UTF-8 validation; MappedText.Validate similarly validates all text for each fragment. Benchmark realistic long pages/joins, validate UTF-8 once at trusted snapshot boundary, then check per-range boundaries. Do not prematurely complicate tiny-document path.
19. **Whole-source supports retained by Slice.** `source/mapping.go` intentionally preserves original broad support plus narrowed exact location. This is correct provenance but can grow support inventories and surprise downstream “only exact citation” consumers. Document exact Location vs support ancestry; do not delete broad supports blindly.
20. **Resolve region returns whole media.** `layout/resolve.go:Resolved` says Bytes original media, not cropped. Keep Original/OriginalRegion fields and require caller cropping where needed. UI crop/render and OCR scheduling do not belong in ragy core.
21. **Coverage conservatism is deliberate.** Project applies document coverage to every page projection; ApplyOCR marks partial even recognized text and keeps original text untouched. Explain whole-document vs per-element coverage in API examples. Do not promote OCR to verbatim or complete based on successful model call.
22. **Optional ImageText replaces OCR mapping rather than merges/fallbacks.** If callback returns empty, Project drops image text even when recognized OCR exists; intentional explicit callback authority is preferable to hidden recovery. Document and test selection rule, or expose a named host policy to combine outputs.
23. **Multimodal URL is transport-neutral.** `multimodal.Part.Validate` accepts arbitrary absolute schemes and trims for validation without normalizing original field. Provider adapters must enforce supported schemes, MIME/wire validity and original whitespace handling; host owns network allowlist and credentials. Do not put a generic downloader/SSRF policy service in this library. Valid UTF-8 text and strict inactive-field shape can be centralized if contracts require it.
24. **Evidence admission and payload privacy are mostly well bounded.** Scope metadata and source admission precede hit identity policy, immutable record owns bytes, source relationships validated, protection failure cannot become best effort success. Keep exact tests; sink privacy beyond record and side effects after revocation remain host responsibility as docs state.
25. **Evidence publication membership excludes Transformation.** `evidence/capture.go:belongs` matches namespace/source/revision/access, unlike source.Reader which also matches transform and target. README explicitly states current narrower tuple; decide whether evidence refers to original source regardless of index transform (legitimate) or claims published artifact membership. Document this distinction; do not blindly force index target transform onto original PDF/text citation.
26. **Evidence numeric representation of Rank.** capture casts int rank to float64; very large int ranks could lose identity. Real retrieval ordinal should be collection-bounded, so define maximum rank vs semantic position (not arbitrary external numeric ID), reject outside representable/meaningful bounds. No evidence of production large-rank use.
27. **Evidence input work bounds vs wire bounds.** boundedInput limits stage/hit/sources/location arrays but not all document mapping/support or contribution location nested input before expansion. Output bounds are not CPU/allocation bounds. Clarify host input-size ownership or add early bounded traversal for public capture endpoints; benchmark rather than promise a universal fixed total memory budget.
28. **Package-local docs discoverability.** chunking/evidence have focused READMEs; source/documents/layout mostly rely on Go docs + historical task13/task14. Add small current integration guide linking exact retained source→layout→chunk→index projection→authorized resolve, and documented ownership/bounds/error/partial semantics. Historical acceptance reports are evidence, not primary API manual.

## Boundaries and retained strengths

Independent ragy should own retrieval-ready source identities, chunking/index projection, parser-neutral layout, scoped source-reader contracts, exact/support-only provenance and retrieval evidence export. It should not own blob retention service, domain auth rules, agent memory, generalized evaluation framework, agent harness loop, product UI, OCR/model orchestration or retries. Bring-your-own metadata and explicit callbacks preserve these boundaries. Existing no-latest source access, immutable mappings, explicit partial coverage, separate Context vs original Content, and no hidden evidence retry are good architectural decisions. Clean break should simplify ambiguous contracts above while preserving these guarantees.
