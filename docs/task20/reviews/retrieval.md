## Confirmed defect R-01 — P1: local recipe deadline suppresses a non-skippable provider failure and releases prior evidence

References: `recipe/run.go:304–323` (`settle`, particularly 320–321), `recipe/run.go:214–230` (`boundedStop`), `recipe/run.go:416–435` (`stop`); contract `recipe/README.md` sections Budgets/outcomes/failures and Optional recording; `access/access.go:15–18` explicitly prohibits rescuing ProtectionError into success.

Trigger through supported public ports:
1. `recipe.New(Config)` with scoped binding, `SingleRewrite`, injected clock, Duration=5 seconds; original backend retrieval successfully captures d1.
2. Planner is dispatched legally within budget. It returns a legitimate `access.NonSkippable(ragy.ErrUnavailable)` failure (e.g. the port's own source/authorization check fails). While work ran, recipe clock crossed attempt deadline by one second. Host authority binding still passes and has not expired (one-minute expiry). Usage is known and within reservation.
3. `settle` observes deadline and returns only `errors.Join(gateErr, settleErr)`, discarding **callErr**. `stop` converts deadline to bounded partial; RRF assembles prior d1 and `RunOwn` returns nil error with selected evidence. Replacing callback error with `ragy.ErrProtocol` also incorrectly returns successful partial.

Actual output in `/tmp/ragy-review-retrieval-repro.log`:
```
protocol: error=<nil> classRetained=false outcome=partial selected=1 queries=1
protection: error=<nil> classRetained=false outcome=partial selected=1 queries=1
```
Repro: `/tmp/ragy-review-retrieval-test.go`, overlay `/tmp/ragy-review-retrieval-overlay.json`.
Command from root: `GOCACHE=/tmp/ragy-review-go-cache go test -overlay=/tmp/ragy-review-retrieval-overlay.json ./recipe -run '^TestReviewDeadline' -count=1 -v`.
The fixture uses no sleeps, concurrent mutation, remote provider or malicious callback; clock advancement inside the synchronous planner makes normal elapsed time deterministic. It intentionally asserts error != nil and fails against current SHA. Public `RunOwn` is exercised; the external-package fixture just supplies normal configured ports.

Impact: explicit fail-closed protection barrier is violated; prior payload survives a failure which contract requires to suppress every payload and side output. This is **not** a demonstrated cross-tenant source read: the returned d1 was captured before the failure. P1 is justified by converting explicit non-skippable authorization/protection failure into nil-error payload delivery. Protocol case is same root cause, not separate defect/count.

Required direction: preserve callback failure and settlement information regardless of final timing gate, with explicit priority for non-skippable protection, malformed output and usage exceeded over bounded local timeout. Simply joining all errors is insufficient: `boundedStop` currently permits protection when the joined error also matches DeadlineExceeded. Distinguish attempt-local timeout from a separately protected callback failure; do not demote mixed errors by `errors.Is` membership alone. Ordinary callback errors must remain failures per README; only actual bounded-stop conditions without higher-priority causes may deliver captured evidence. Keep reservations accounted once, do not retry the model.

AAA acceptance:
- Arrange successful original retrieval then planner crossing injected deadline with protection/protocol/ordinary sentinel; Act public Run/RunObserved and RunOwn variants; Assert protection gives empty result/journal and nonnil protected error; ordinary/protocol Run returns no payload, RunObserved may retain permitted failed journal only, and errors.Is retains original cause.
- Repeat at backend, assessor and QueryEncoder settlement boundaries where they share settle; include callback protection joined with context.DeadlineExceeded.
- Pure local deadline without callback fault continues to return documented bounded partial; parent cancellation remains suppressive.
- Known usage overrun plus timeout is never success; unknown usage remains conservatively reserved; no duplicate dispatch.

## Separate architecture / naming / complexity decisions (not confirmed bugs)

1. **Keep bounded recipe execution in ragy.** `recipe/contracts.go`, README: explicit single rewrite, max-two multiquery and depth-one decomposition are retrieval algorithms, not an agent harness. Preserve host planner/assessor/encoder/pricing ports and no conversation/action loop. No additional library is needed for these algorithms.
2. **Delete or mark deprecated compatibility façade `ranking`.** `ranking/ranking.go:1–4` already directs new code to retrieval; three aliases + duplicate constructors + reranker interface add an import path without independent responsibility. Clean break can remove it after usage inventory; don't move algorithms merely to rename the package.
3. **Unify internal result-only and execution-aware composition engines.** `retrieval/orchestrator.go:34,522,845` and `retrieval/execution.go`: parallel fallback/rescue/aggregate/pipeline stacks multiply fixes and error-policy drift. Retain one execution engine with zero metadata specialization; preserve currently public convenience API only if it adds actual value.
4. **Remove hidden score-merge fallback on custom fusion failure or make explicit policy.** `retrieval/orchestrator.go:351–413`: configured merger fails, implementation unconditionally sequentially merges by score, possibly returning a prefix on incompatible scales. It carries an error and is documented, so not a silent success defect; still unusual semantic change. Prefer error+original observed sets or explicit host-specified degraded merger. Never compare heterogeneous scores automatically.
5. **Zero execution metadata is not absence.** `retrieval/execution.go:993–999` `reflect.DeepEqual(returned, zero)` reuses incoming metadata. A legitimate zero result cannot clear prior state. Choose explicit presence semantics or always honor returned value; do not add reflective guessing. Treat as current design contract unless caller-visible guarantee says otherwise.
6. **Separate presence of partial error from result source.** `retrieval/partial_failure.go:34–49,68–99` searches first nested PartialFailureError and prefers its Result over separate rs; synchronization constructs a new partial error and may lose outer wrapper context. Define joined-error preservation and single authoritative result, with errors.Is/As tests. No targeted lawful pipeline loss reproduced here, so not another confirmed bug.
7. **Make nil configuration validation consistent.** `recipe/run.go:56–78` rejects typed-nil Backend/Identity but optional QueryEncoder uses ordinary nil elsewhere; postprocessor-chain constructor admits nil element then dispatches at `retrieval/postprocessor_chain.go:137`. Define programmer-error contract, preferably constructor error/invalid processor rather than dispatch panic. Invalid caller configuration is not claimed as a live valid-input bug.
8. **Document resolver extraction fallback.** `retrieval/resultset.go:27–39` ResolverFor recognizes only built-in resultset and silently defaults custom sets; `NormalizeRankOnlyResultSet` uses it. Either explicit resolver argument or optional capability; avoid implying universal resolver preservation for arbitrary BYOT sets.
9. **Clarify score threshold stage.** `retrieval/postprocessor_chain.go:123–128` applies threshold before processors; terminal-options helper applies threshold after root. Reranker can replace semantics. Make stage explicit in docs/API, keep incompatibility rejection, avoid threshold being mistaken for a final reranked-score cutoff. No evidence current explicitly selected prethreshold contract is violated.
10. **Revisit merged-payload/source support semantics.** `retrieval/resultset.go:187–207` winner-by-key combines support locators and score histories even if losing content differs; RRF separately refuses different payloads under same key. State clearly whether MergeKey denotes identical evidence or host-defined business grouping. Keep GroupBy as explicit content assembly; do not infer textual entailment from key equality. Current API explicitly permits winner selection, so not count as bug.
11. **Snapshot or explicitly freeze pointer configuration.** `recipe/contracts.go:137` Artifact pointer and callbacks stored by value in recipe.New; immutable configuration ownership should be documented. BYOT input stability during capture is already well stated; do not expand into arbitrary reflection cloning.
12. **Retain conservative accounting semantics.** `recipe/budget/budget.go:136–185`, README: calls never refunded, unknown usage reserved, explicit clock+real timer, no organization quota. This is appropriate. Single boolean Usage.Known combines tokens+host-priced cost and can suppress known tokens when cost unknown; if refined, split known dimensions rather than report false zero/known cost. Do not replace with metry billing/scheduler.
13. **Name budget scopes more precisely.** package comment says attempt-local, but shared ledgers intentionally span concurrent Run attempts. Describe supplied scope as host-selected budget scope; RunOwn independent. Keep method distinction; don't introduce global singleton quotas.
14. **Explicit model-free attestation is honest, not enforceable sandboxing.** BackendModelFree plus UnsupportedQueryEncoderBridge prevents accidental model budget claims but cannot prove arbitrary host code. Bridge's Embedder field is never used (`recipe/encoding.go`); remove field or replace bridge with explicit adapter capability diagnostic. Never call unsupported encoder as fallback.
15. **Cache capacity is entry count, not byte bound.** MemoryCache maxEntries + metadata clone outside lock are good; Store uses O(capacity) LRU eviction scan (`retrieval/cache.go:111–125`). Document memory-size limits/complexity, optimize only with measured need. No distributed/singleflight/refresh scheduler belongs here by default.
16. **Avoid repeated bulk copying solely to preserve shape.** RewrapResultSet, Documents, ensureResultSet and aggregation repeatedly copy ragy slices; BYOT metadata is intentionally not cloned in generic retrieval. Measure large result-set paths before introducing internal owned-result optimization. Keep external ownership guarantees and test mutation isolation.
17. **Clarify boundedness of model-produced text.** Recipe bounds query count and requires model port enforce input/output token maxima, but does not itself bound planning string bytes; MaxDocuments bounds count rather than metadata/content bytes. This is acceptable only under stated trusted bounded ports. Explicitly document that recipe cannot bound allocations of arbitrary callbacks; do not claim MaxDocuments as memory ceiling. Optional bytes admission can be useful, but avoid global hardcoded 16 MiB fallbacks.
18. **Retain explicit distinction Fallback vs Rescue.** Existing empty-success vs empty-error behavior avoids masking partial result failures; names and README must always explain it. General retries/model selection remain host/router responsibilities; route-switch retrieval alternatives fit ragy.
