# TASK18 reproducible benchmark workload

Baseline implementation: `dd3b0f1b379ce0d5fbcfd543336b2d6093228a5b` (TASK17). Benchmarks were added before production optimizations. New required configuration fields after optimization preserve fixture capacity and corpus: managed lexical MaxCachedSnapshots32; managed graph MaxAdmissionRecords2*N matches its existing MaxRecords2*N. Frozen baseline uses the earlier API without these fields.

Environment: Go `go1.27.1 darwin/arm64`, Apple M1 Max, Darwin 27.0.0 arm64, `-cpu=4` (GOMAXPROCS4). `statfs("/tmp")` reports **APFS**, 4096-byte blocks, `/dev/disk3s1`, mounted `/System/Volumes/Data`. Benchmarks use local APFS temporary directories; filestore CAS explicitly roots at `/tmp`, while managed/persistent `b.TempDir` uses the OS temp root `/private/var/folders/.../T` on the same Data volume. No network database. Persistent fixture setup, staging, publication, corpus generation, and scope capture are outside timers. Query results and returned metadata are fully materialized. Warm OS caches are allowed, fsync remains in measured CAS. Background system load is uncontrolled, and setup/GC from other benchmark packages can interfere; compare allocation counts as well as elapsed samples.

Initial capture command: `sh docs/task18/run-benchmarks.sh before`. Frozen baseline harness source is retained as `.go.txt` evidence under `harness-before/`; `sh docs/task18/prepare-baseline.sh /tmp/ragy-task18-before-source` reconstructs the baseline checkout from the fixed commit plus those harnesses. These evidence files use the original managed API and are not compiled into current production. Final comparison uses `sh docs/task18/run-serial-benchmarks.sh before /tmp/ragy-task18-before-source`, followed by `sh docs/task18/run-serial-benchmarks.sh after` on final code, in a quiet measurement window. Both serial runs explicitly use `TMPDIR=/tmp`, local APFS, with otherwise identical fixtures and flags. Original overlap logs remain retained; their summary is `results/initial-baseline.md`. `python3 docs/task18/summarize-benchmarks.py` generates measured static tables and CSV under `results/` from serial logs. Each row has three independent Go benchmark samples, fixed 100ms minimum measurement duration, ns/op wall time, B/op, allocs/op. Expensive operations can produce one iteration per sample. CPU model appears in raw Go logs; ns/op is elapsed time. Each final serial command is additionally wrapped with `/usr/bin/time -l`; separate `serial-*-process-stats.txt` files record whole-process user/system CPU seconds, wall time and platform-reported maximum RSS, including untimed fixture setup and any compilation. Those process measurements are not per-query CPU or memory limits and should not be divided by benchmark iterations to claim such limits. Race validation is run separately and cannot be used for performance comparisons. There are no absolute SLOs in this workload.

| Profile | Fixture and timed operation |
|---|---|
| Lexical bulk | N=100/1000/10000; documents in ascending IDs; each has 21 tokens: 16 `common`, four `bucket{i%100}`, one `unique{i}`. 100 bucket vocabulary, N unique terms, no random seed (deterministic formula). `Index` full atomic replacement including tokenization; existing index object reused. |
| Lexical rare/common query | Same corpus. `unique0` matches one document; `common` matches all N. TopK10, unrestricted read, no optional filters. |
| Lexical update | Same corpus. Upsert existing document `i%N`, identical content, one mutation per operation; aggregate statistics work and removal/reinsertion measured. |
| Lexical concurrent | Four Go benchmark workers; shared atomic operation counter schedules each tenth operation as update, other nine as `unique0` TopK10 retrieval. The counter establishes 90/10 totals; goroutine interleaving intentionally uncontrolled. Throughput ns/op is across all operations, not request tail latency. |
| Managed lexical | N=100/1000/10000; actual staged/published records, one captured pinned publication, mandatory scope selects either100% or10%. Repeated same identity read includes freshness and publication gates, excludes staging/capture. Three-token content `searchable document token{i%17}`; mandatory tenant-a scope selects the contiguous first percentage, remaining records tenant-b. Scalar metadata and no recording clone callback. Store budget128MiB. |
| Managed graph | N=100/1000/10000 nodes, N-1 directed chain edges, fixed revision/publication. Scope100%/10%; AdmitTraversal, FindByIDs, Traverse measured separately. Traverse seed first node, depth4, MaxNodes16/MaxEdges16. Full admission can still scan N despite bounded output. |
| Filestore CAS | Retained sizes10/100/1000 manifests; one distinct source and current publication per manifest; artifact counts1 and32 are separate fixed fixtures, each artifact has one support. Fixed count each sample; generation increments via CompareSwap. 64MiB snapshot budget. Report serialized snapshot-bytes after measured operation; namespace reads, validation, marshal, durable write/fsync and returned cloning included. No history retirement in baseline workload. |
| Current-format retirement layout comparison | Separate `BenchmarkTask18Retirement` fixture: N=10/100/1000 confirmed-cleaned old/owner pairs (2N manifests, N cleanup jobs),32 artifacts per old manifest. Compare ordinary CAS on the same layout before vs after explicit Maintain; setup and maintenance excluded from CAS timer. Each owner is the active tombstone. Snapshot-bytes includes retained identities, exact artifact fences and cleanup receipts. This comparison uses the current implementation on both sides and is distinct from original active-publication before/after measurements. |
| Persistent dense | N=100/1000/10000, dim32, deterministic signed basis vectors, one captured tenant-a scope, exact full query TopK10. |
| Persistent tensor | Same N/dim32; four document vectors, two query token vectors. Candidate lists evenly select10% or100% of corpus, TopK10. Candidate construction outside timer; candidate-only exact MaxSim plus admission/file read included. |

Fixed-size history CAS measures cost at retained history sizes; it does not simulate unknown jobs, live pins or cleanup fences. Graph chain is a deliberately simple reachable shape, not evidence about arbitrary degree/cycles or private bridges. Existing adversarial correctness tests cover those separately. Corpus content is small, single namespace with fixed revision/publication, and vector dimension32 is a profiling fixture rather than a recommended production embedding dimension. Query wall-time means do not establish p95/p99 latency. Run longer samples and representative host metadata/payloads before capacity decisions.

Raw evidence is in `results/before-core.txt`, `before-managed.txt`, `before-history.txt`, `before-persistent.txt` and matching after files. Baseline files are retained unchanged after production edits. Environment probes for diskutil/sysctl were unavailable in sandbox; filesystem type was verified through native libc statfs, CPU comes from Go benchmark headers.
