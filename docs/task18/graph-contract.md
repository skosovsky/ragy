# Managed graph admission and traversal contract

The managed graph is a volatile embedded target. The low-level `graph.Port` contract is unchanged. Lifecycle manifests persist independently; a restarted adapter without retained fact inventory returns unavailable until the host restores/reindexes that inventory.

`Config.MaxRecords` limits one staged payload or one host basis. `Config.MaxAdmissionRecords` limits the sum of selected node and edge records across all selected publications and the optional host basis. It must be positive at construction; zero and negative values are invalid. This finite host profile counts records before scope filtering, conflict removal, or fact deduplication, including shared facts supported by multiple versions. Admission exceeding the limit fails with an error wrapping `ragy.ErrInvalidArgument`; no partial view or delivery metadata callback escapes. Hosts that select multiple publications must size this independent limit explicitly.

`Request.MaxNodes` and `MaxEdges` limit results, not pre-traversal CPU or admission memory. `AdmitTraversal` validates request/scope/publication shape without loading facts and cannot predict selected fact capacity. Both `Traverse` and `FindByIDs` enforce admission capacity during the actual read.

Every selected fact is checked against the prepared mandatory/query scope before adjacency construction. Conflicting facts remain diagnostics and are removed from traversal. Only admitted edges whose source and target both remain admitted nodes enter outbound/inbound adjacency. Traversal scans incident admitted edges rather than scanning the entire admitted edge map at each expansion. Undirected traversal includes a self-loop once. Cycles use visited node and edge sets; original source supports and host basis identities survive shared facts.

Per-read fact admission is linear in selected records plus selected target artifact inventories and attached supports, with maps and adjacency proportional to admitted unique facts and supports. Walk cost is proportional to visited nodes and incident edges examined within the requested depth; returned node and edge identifiers are sorted. The lifecycle store load/validation and publication/version selection still scan retained metadata; these are outside the fact admission cardinality limit. Record identifiers, metadata/attributes and support arrays have host-controlled byte sizes, so this limit is not a complete CPU, memory-byte or namespace-history bound. No cached IAM decision, hidden refresh, ANN or distributed graph service is provided.

Freshness checks remain before selection, during admission, adjacency construction and expansion, and before/after host metadata delivery callbacks. Version payloads captured under the adapter lock remain immutable for readers. Revoke/cancellation gates fail closed; cleanup and host-basis release retain their existing captured-publication semantics.
