# Local capability and scale profiles

This matrix describes algorithm/storage contracts. TASK-18 acceptance and measured scaling results identify executed checks; implemented local profiles do not imply verification against external database/provider services.

| Implementation | Retrieval algorithm / scope | Retention and restart | Explicit limits and costs |
|---|---|---|---|
| `lexical.BM25Index` | Exact BM25; mutable volatile corpus. A query copies matching term postings/candidate rows and retains corpus-level statistics. Updates maintain length aggregates. | Atomic rebuild/read snapshot; corpus does not survive process restart. Scoped read snapshots are separately constructed over admitted documents. | Rare queries scale with matching postings/candidates; common queries can still visit and rank the whole admitted corpus. Tokenization and BYOT metadata bytes remain host-sized. |
| `lexical/managed` | Exact BM25 over freshly admitted pinned inventory; no private corpus statistics. Repeated reads may reuse a matching immutable snapshot. | Corpus is volatile; durable lifecycle metadata does not reconstruct it. Missing retained versions fail explicitly. Retirement/cleanup does not resurrect old snapshots. | Required LRU snapshot-entry capacity; repeated lifecycle/inventory/freshness checks remain. Entry limits are not a universal byte quota for host metadata/corpus. |
| `graph/managed` | Mandatory node/edge scope and conflict admission before adjacency/traversal. Exact traversal of the admitted graph, with shared-source provenance. | Volatile graph/basis data; durable lifecycle metadata alone cannot restore it. Host basis has its own explicit identity/retirement contract. | Required selected-fact admission cardinality and separate output node/edge limits. Metadata loading, admission maps/support checks and high-degree incident lists still cost work before/within traversal. Output limits alone are not end-to-end CPU/memory bounds. |
| `dense/persistent` | Exact vector scan under required pinned publication and scope; declared metric/space identity. | Versioned local artifact files plus lifecycle ledger; reopen/inventory validation required. | Configured record/scan/byte bounds; work scales with scanned records and vector dimension. No ANN or hidden remote service. |
| `tensor/persistent` | Exact MaxSim only within explicit candidate list, with declared space/metric and scope. | Versioned local artifacts plus lifecycle ledger; retained inventory verified on read. | Candidate and record/byte limits; work scales with candidates × query vectors × document vectors × dimension. Candidate-only exactness is not exhaustive corpus recall. |
| `lifecycle/filestore` | Full namespace generation CAS, flock, atomic rename and directory fsync on supported local Unix filesystem. | Durable v2 metadata, immutable retired identities/fences and registered pin reservations. Maintenance only compacts eligible metadata; source/target payload and authority remain host-owned. | Explicit total snapshot-byte capacity includes skeletons, jobs, fences and pins. Full read/validate/marshal still scale with retained metadata. Skeletons/fences can grow to capacity; refusal is explicit, with no automatic deletion or constant-space claim. |

APFS measurements are local profiling evidence, not a guarantee for other filesystems, network mounts, distributed transactions or cross-host locking. Host callbacks must cooperate with context and be stable/thread-safe; arbitrary payload bytes and callback allocation cannot be bounded by an entry-count limit. Cache fingerprints/digests are internal identities, not authorization and not a privacy substitute.

Current measured workload, corpus/scope/revisions and environment: [workload](workload.md). Raw benchmark logs and serial measurement report are retained under `results/`. Before/after evaluation must use the same corpus and limits, and separate allocation evidence from elapsed-time variability. No p95/p99 or production SLO is inferred from these small sample runs.
